# On-Device Human Activity Recognition on ESP32 with Int8 Quantization

Project for the University of Helsinki MOOC [*Developing the Artificial Intelligence of Things* (2026-2027)](https://courses.mooc.fi/org/uh-cs/courses/developing-the-artificial-intelligence-of-things-2026-2027).

An ESP32 reads a 6-axis MPU6050 IMU at a fixed 50 Hz, windows the stream into
2.56 s frames and classifies the activity (walking, walking upstairs, walking
downstairs, sitting, standing, laying) **on the device** with a 1D-CNN. The model
is optimised with **post-training int8 quantization** and compared with the
float32 baseline for accuracy, latency and memory footprint. Results are shown on
an OLED and published over MQTT to a small web dashboard.

| | |
|-|-|
| Board | ESP32 DevKit-C v4 (Wokwi simulation) |
| Sensor | MPU6050 accelerometer + gyroscope, I2C, polled at 50 Hz |
| Model | 1D-CNN, 7 446 parameters, TensorFlow Lite Micro |
| Optimisation | full-integer post-training quantization (float32  ->  int8) |
| Wokwi project | https://wokwi.com/projects/475499882644462593 |
| Report | [`report/Report.pdf`](report/Report.pdf), LaTeX source in [`report/Latex/`](report/Latex/) |
| All numbers | [`results/summary.md`](results/summary.md) (regenerated by the scripts below) |

## Results

| metric | float32 | int8 PTQ | change |
|-|-|-|-|
| test accuracy, 9 unseen subjects (n = 2 947) | 90.94 % | 91.18 % | +0.24 pt |
| weight bytes | 29 784 | 7 446 | 4.0x smaller |
| `.tflite` in flash | 36 460 B | 18 352 B | 2.0x smaller |
| tensor arena (ESP32 RAM) | 19 792 B | 7 556 B | 2.6x smaller |
| inference latency, Wokwi, 240 MHz, `-O2` | 110.6 ms | 446.4 ms | see note below |
| sampling under full load | 50.0 Hz, 0 missed deadlines, 0 dropped windows | | |

## Reproducing the results

Tested on Ubuntu with Python 3.12 and an NVIDIA GPU (CPU works too). All scripts
are seeded and TensorFlow runs with deterministic ops; a clean rerun reproduces
`results/summary.md` exactly.

### 1. Host: dataset -> trained model -> quantised model

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
bash data/download_uci_har.sh
cd training
../.venv/bin/python 01_prepare_data.py
../.venv/bin/python 02_train.py
../.venv/bin/python 03_quantize.py
../.venv/bin/python 04_export_c.py
```

`requirements.txt` pins `tensorflow[and-cuda]==2.17.1` and `keras==3.3.3`. TensorFlow
2.16 cannot convert Keras-3 `Conv1D` layers to TFLite; 2.17 is required.

### 2. Device: build the firmware and run it in Wokwi

Prerequisites: [arduino-cli](https://arduino.github.io/arduino-cli) with the ESP32 core
and the libraries used by the sketch.

```bash
arduino-cli core install esp32:esp32@2.0.17
arduino-cli lib install "TensorFlowLite_ESP32@1.0.0" "Adafruit SSD1306@2.5.17" \
  "Adafruit GFX Library@1.12.6" "Adafruit BusIO@1.17.4" "PubSubClient@2.8.0"
firmware/esp32_har/build.sh            # -O2 build  ->  firmware/esp32_har/build/
```

Run it either way:

* **Wokwi for VS Code**: open the folder, `F1 -> Wokwi: Start Simulator`
  (`wokwi.toml` points at the built binary). Green **MODE** button runs the
  18-window benchmark; blue **WALK / UP / DOWN / SIT / STAND / LAY** buttons inject a
  recorded window of that class; the MPU6050 sliders drive LIVE mode.
* **Headless**: reproduces `results/device_log.txt`:
  ```bash
  curl -L https://wokwi.com/ci/install.sh | sh          # wokwi-cli, once
  export WOKWI_CLI_TOKEN=...                            # free token: wokwi.com/dashboard/ci
  firmware/esp32_har/run_wokwi.sh
  ```

The wokwi.com project link above contains the same sources and wiring; the free
online build server times out on TensorFlow Lite Micro, so use one of the two
local options to simulate.

### 3. Metrics, figures, summary

```bash
cd training
../.venv/bin/python 05_parse_device_log.py
../.venv/bin/python 06_make_figures.py
../.venv/bin/python 07_summary.py
```

## How the firmware works

```
MPU6050 --(I2C, 50 Hz poll)--> ring buffer --(128 samples, hop 64)--> standardise --> float32 + int8 models --> OLED / serial / MQTT
                    core 1 (sampler)                                            core 0 (inference task)
```

* **Sampling**: polling with a phase-locked `micros()` deadline (period 20 000 us),
  so jitter never accumulates into drift. The achieved rate, missed deadlines and
  dropped windows are measured and printed, not assumed.
* **Windowing**: 128 x 6 ring buffer; inference every 64 new samples (50 % overlap),
  identical to the training windows.
* **Pre-processing parity**: per-channel mean/std from the training subjects are
  compiled into `har_config.h`; one code path standardises live and replayed windows.
* **Concurrency**: sampler in `loop()` on core 1; inference, OLED and networking in a
  FreeRTOS task on core 0; IMU and OLED on separate I2C controllers (`Wire`, `Wire1`).
* **Both models** run on every window so latency and RAM are compared on identical inputs.
* **MQTT** (`ENABLE_MQTT 1`): one ~150 B JSON message per window to
  `aiot/har/<chip-id>/activity` on `broker.hivemq.com`, QoS 0. Open
  `dashboard/index.html` and click *connect* to watch it. Set `ENABLE_MQTT 0` for a
  fully offline build.

## Wiring (`firmware/esp32_har/diagram.json`)

| part | ESP32 pins |
|-|-|
| MPU6050 | VCC 3V3, GND, SDA GPIO21, SCL GPIO22 (I2C bus 0) |
| SSD1306 OLED, 0x3C | VCC 3V3, GND, SDA GPIO25, SCL GPIO26 (I2C bus 1) |
| MODE button (green) | GPIO4  ->  GND, internal pull-up |
| class buttons (blue) | WALK 32, UP 33, DOWN 27, SIT 14, STAND 12, LAY 13, each  ->  GND |
| on-board LED | GPIO2, on during inference |

## Note on the latency numbers

Wokwi is functionally accurate but not cycle-accurate. `firmware/wokwi_timing_bench`
shows 170 k float multiply-accumulates take 167 ms of simulated time (~240 cycles
each; real silicon needs 10-20) and 64-bit integer maths is about 4x slower again. The
reference int8 kernels in TensorFlow Lite Micro requantise with 64-bit multiplies,
so in Wokwi the int8 model is *slower* than float32; on a physical ESP32 with
Espressif's ESP-NN kernels int8 is the fast path. Flash and RAM figures are
independent of the simulator. The report discusses this in detail.
